# Where's the bug?

This project will benchmark which function a self-healing coding agent should
read first after a test fails. Ground-truth cases will be generated by placing
one AST mutation in one known function and retaining mutations caught by tests.

## Phase 0 feasibility result

The target is the vendored `toolz` 1.1.0 source and test suite at upstream
commit `568c2b8393973cd172a466546c9d95779c452438`. The environment uses Python
3.11.15 and pinned packages in `pyproject.toml` and `uv.lock`.

The complete vendored suite passed: 186 tests in 0.22 seconds in the independent
Phase 0 reproduction. Because the complete suite is below the five-second
feasibility threshold, harvesting runs the complete suite for each mutant. It
does not select tests by mutated module.

The production library contains 155 functions and methods across 14 Python
source files. The deterministic syntax scan found 1,040 candidate mutation
sites:

| Operator family | Candidate sites |
| --- | ---: |
| Arithmetic swap | 21 |
| Boolean constant swap | 42 |
| Boolean operator swap | 27 |
| Comparison flip | 62 |
| Integer off-by-one | 75 |
| Remove `not` | 25 |
| Return value replaced with `None` | 221 |
| Slice-bound off-by-one | 10 |
| Statement deletion | 557 |

The scan excludes tests and docstring deletion. A return that already returns
`None` is not a candidate. A statement is deletable only when another statement
would remain in that body. Phase 1 will deduplicate generated source before any
mutant is executed.

## Mutation harvest

The mutator enumerated 1,107 unique source-changing mutants. The deterministic
sampler selected 400 mutants across 153 functions, capped at four mutants per
function. The measured outcomes were:

| Outcome | Mutants |
| --- | ---: |
| Killed | 373 |
| Survived | 27 |
| Timeout | 0 |
| Invalid | 0 |

The observed kill rate was 93.25%. Mutants have a hard 20-second timeout; none
reached it in the final harvest. Every outcome remains recorded in
`data/mutants.jsonl`.

The 373 killed mutants form the committed benchmark in `data/cases.jsonl`.
Cases are split by function, never by individual case:

| Split | Functions | Cases |
| --- | ---: | ---: |
| Development | 75 | 187 |
| Test | 75 | 186 |

No function appears in both splits. Development results and confidence
intervals appear below; the held-out test results remain intentionally `TBD`.

## Evaluation harness

The original source is indexed once as 155 function-level candidates. For each
case, the index replaces only the known mutated function chunk. Source-token
cost uses `tiktoken` with the `cl100k_base` encoding.

The evaluator reports Top-1, Top-5, MRR, mean and median rank, mean and median
tokens-to-hit, and p50 and p95 query latency. Every aggregate includes a
95% confidence interval from 1,000 bootstrap resamples with seed 2027.
Comparisons use paired resampling over identical case IDs.

Phase 2 evaluated only a stable candidate-order sanity check on the 187
development cases. This check is not a proposed localization technique. Its
measured Top-1 was 0%, Top-5 was 4.813%, MRR was 0.036, median rank was 80, and
median tokens-to-hit was 7,531. That validation result remains in the experiment
log; `results/results.json` now contains the Phase 3 baselines. The test split is
locked in the evaluator and has not been run.

## Baseline localizers on development data

| Localizer | Top-1 | Top-5 | MRR | Median rank | Median tokens-to-hit | p50 latency |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| L0 random | 0.000% [0.000, 0.000] | 2.139% [0.535, 4.278] | 0.030 [0.023, 0.038] | 76 [60, 88] | 9,491 [7,673, 10,648] | 0.0228 ms |
| L1 stack | 26.738% [20.856, 33.168] | 30.481% [24.064, 36.912] | 0.299 [0.242, 0.363] | 34 [25, 55] | 4,041 [2,443, 5,390] | 0.0371 ms |
| L2 BM25 | 36.898% [29.947, 43.850] | 57.219% [50.267, 64.184] | 0.469 [0.406, 0.531] | 3 [2, 5] | 617 [376, 906] | 17.8245 ms |
| L4 stack + BM25 RRF | 27.273% [20.856, 33.690] | 45.455% [37.968, 52.406] | 0.376 [0.320, 0.436] | 7 [4, 11.025] | 967 [530, 1,657] | 17.8701 ms |

BM25 is the strongest baseline on development data. Equal-weight reciprocal
rank fusion made it worse: BM25's paired MRR advantage over the hybrid was
0.093 with a 95% interval of [0.028, 0.156]. This negative result is retained.

The error breakdown explains the stack heuristic. Its Top-1 accuracy was 0% on
97 `AssertionError` cases and 55.556% on the 90 other cases. Assertions usually
end in test code, while runtime exceptions often expose a library frame.

The dense baseline is optional. `python -m faultloc eval --dense` attempts the
`BAAI/bge-small-en-v1.5` ONNX model and skips it with a clear reason if the
optional package or model is unavailable. It was not installed for these
results, so no dense numbers are reported.

## Development improvements

Direct test-call extraction improved BM25. A5 parses the failing test source,
resolves directly called library function names, and moves those candidates to
the front while preserving BM25 order. It reached 44.385% Top-1, 64.706% Top-5,
0.543 MRR, median rank 2, and 354 median tokens-to-hit. Its paired MRR advantage
over BM25 was 0.073 with 95% interval [0.042, 0.107]. **KEEP.**

The final development winner is A6 routing. Non-assertion failures with a
library traceback frame use the stack heuristic. All other cases use A5. It
reached 54.545% Top-1, 65.241% Top-5, 0.603 MRR, median rank 1, 251 median
tokens-to-hit, and 10.6639 ms p50 latency. Against A5, it improved MRR by 0.061
[0.018, 0.101] and reduced p50 latency by 7.574 ms [4.811, 9.462]. **KEEP.**

Query cleanup did not help. A7 removed pytest boilerplate and file paths before
BM25. Its MRR fell from 0.469 to 0.455. The paired BM25 advantage was 0.014
[0.003, 0.027], although cleanup reduced p50 latency by 0.948 ms. Measurement
quality takes priority over that small speedup. **REVERT.** The implementation
remains available only through `python -m faultloc eval --experiments` so the
negative result is reproducible.

The optional static-call-graph expansion was not attempted. The three planned
core experiments already produced a clear quality-and-latency result within the
one-day scope.

## Dashboard

The FastAPI dashboard reads `results/results.json` and `data/cases.jsonl` once
at startup. It does not harvest mutants or run an evaluation. The leaderboard
shows every cached estimate with its bootstrap 95% confidence interval, the
error-type cards explain the winning A6 router, and the case explorer exposes
the mutation diff, failing-test source, traceback, rank, and tokens-to-hit for
each localizer. Only the 187 evaluated development cases are exposed; the test
split remains sealed.

The Replit Run button starts the dashboard on `0.0.0.0` and honors Replit's
`PORT` environment variable. The same server can be started locally with:

```bash
uv run python -m faultloc serve
```

Cached data is also available through `/api/results`, `/api/cases`, and
`/api/cases/{case_id}`. `/healthz` provides a lightweight readiness check.

## Reproduction

```bash
uv sync --python 3.11
uv run pytest
uv run python tools/phase0_stats.py
uv run python -m faultloc harvest
uv run python -m faultloc eval
uv run python -m faultloc eval --experiments
```

On Replit, package installation is driven by `pyproject.toml`; the Run button
executes `python -m faultloc serve` from `.replit`.
